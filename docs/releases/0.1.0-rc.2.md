Evaluation release for porting workers and comparing representative workloads against the incumbent queue.

- Producer-supplied enqueue idempotency keys: matching retries return the original job; conflicting requests return AlreadyExists. The Bun client retries transient failures only for keyed submissions.
- Queue-pressure metrics: sampled queue depth, oldest due age, expired leases, first-claim and due-wait histograms, plus sampling health.
- Grafana dashboard and tested Prometheus alert examples, packaged in `anvilmq-observability-0.1.0-rc.2.tgz`.
- Helm `metricsQueues` allowlist enables named-queue metrics with bounded cardinality.

Use the matching `anvilmq-client-0.1.0-rc.2.tgz` client and `anvilmq-0.1.0-rc.2.tgz` Helm chart. The broker image targets Linux amd64. Check `SHA256SUMS` and pin the image digest from `image.txt`.

Upgrade the broker before enabling keyed retries: rc.1 ignores the new request field and cannot deduplicate enqueue retries. Startup adds an enqueue-receipt table and pressure index; allow time/storage for index creation on an existing backlog. Take a storage-consistent backup before upgrading. Helm rollback does not revert database contents.

Receipts are retained indefinitely and include request payloads. Monitor PVC usage. Pressure sampling adds read/index overhead; production-storage performance remains to be measured.

This remains a single-broker evaluation deployment without HA, authentication, or TLS. Use an isolated namespace/PVC and redirected or disabled business side effects. Worker processing remains at least once; handler side effects still need idempotency. The client is intended for Bun and is not a drop-in replacement for the incumbent queue client.

See [deployment instructions](https://github.com/kofno/AnvilMQ/blob/v0.1.0-rc.2/docs/release-and-deploy.md) and [observability setup](https://github.com/kofno/AnvilMQ/blob/v0.1.0-rc.2/docs/observability.md).
