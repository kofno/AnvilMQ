Evaluation release focused on broker operability and TypeScript client resilience. Includes changes since rc.3; remains a single-broker deployment without HA, authentication, or TLS.

## Broker and deployment

- Graceful SIGTERM shutdown drains RPCs and checkpoints the SQLite WAL before exit.
- Runtime configuration for lease duration, expired-lease recovery interval and batch size, and maximum execution depth.
- Opt-in consistent local database snapshots with bounded retention and backup telemetry.
- Optional Azure Blob snapshot upload sidecar using Azure Workload Identity, plus a restore runbook and failure-testing drills.
- A production-oriented Helm values overlay enables fairness and local snapshots and supplies resource and recovery settings. This overlay deliberately selects NORMAL durability; the base chart retains FULL durability. Blob upload remains disabled until explicitly configured.

## TypeScript/Bun client

- HTTP/2 keepalive, jittered exponential poll backoff, and connection-lost/restored callbacks for broker outages.
- Worker health snapshots and an optional HTTP probe listener distinguish worker liveness from broker-dependent readiness.
- Bounded enqueue retries reuse one idempotency key per call, automatically generated unless explicitly supplied or disabled. Bulk enqueue and child bulk enqueue support bounded concurrency.
- An outbox interface and in-memory implementation support buffering while the producer remains alive.
- Configurable worker concurrency, per-claim heartbeats, and adaptive idle polling.
- Job lifecycle hooks, client Prometheus metrics, injectable logging, and a graceful-shutdown helper.
- The simulator now uses these client capabilities and includes client metrics and a Grafana dashboard.

## Evaluation and upgrade notes

Use the matching `anvilmq-client-0.1.0-rc.4.tgz`, `anvilmq-0.1.0-rc.4.tgz` Helm chart, and `anvilmq-observability-0.1.0-rc.4.tgz`. The image targets Linux amd64. Verify `SHA256SUMS` and pin the image digest from `image.txt`. The client remains a Bun-oriented TypeScript archive; this release does not publish an npm package or compiled Node.js distribution.

Take a storage-consistent backup before upgrading and allow for a single-broker interruption. Preserve the existing PVC and review any values overlay before applying it. Helm rollback does not revert database contents. When shortening broker leases, configure worker heartbeat intervals with sufficient margin below the lease duration.

NORMAL durability permits loss of recent acknowledged writes after OS/power failure. FULL requests commit synchronization and depends on retained storage honoring it. Local snapshots on the broker volume do not survive loss of that volume: configure and verify off-volume upload for that failure model. Recovery is limited to the latest successfully completed, available snapshot; capture/upload failures can make it older than the configured cadence. Snapshot restore can both lose newer submissions and replay previously processed work.

Processing remains at least once; external side effects must be idempotent. Auto-generated enqueue keys protect retries within one call, not a new call after a producer restart. Persist a business key and the original request when retries must span process lifetimes, and account for broker receipt retention. The shipped in-memory outbox is not crash-durable; durable buffering requires an application-supplied store. Handlers must cooperate with cancellation when claim ownership is lost.

Use an isolated namespace/PVC and trusted private networking, with redirected or disabled business side effects during evaluation. This release adds no replication or rolling-upgrade availability, and makes no new throughput or availability guarantee.
